# 要件定義書: ランチルーレット

## 1. 概要

会社などでの昼食の候補選びに迷った際、候補からランダムに1つを選んでくれるWebアプリを作る。
GitHubからZIPでダウンロードし、`index.html` をダブルクリックするだけで動作する、サーバー不要のシンプルなアプリとする。

## 2. スコープ外

- DB、API通信、ログイン機能
- 画面を閉じた後のデータ永続化（候補リストなどはリロードで初期状態に戻ってよい）

## 3. 機能要件

### 3.1 ランチ候補管理

- 初期候補として以下の6件を表示する
  - 🍜 ラーメン / 🍛 カレー / 🍣 寿司 / 🍝 パスタ / 🍱 定食 / 🍲 うどん
- 候補は画面から追加できる
- 候補は画面から削除できる
- 候補は最低2件を維持する（2件のときは削除操作を行えない、または無効化する）
- 候補数の変化に応じて、ルーレットの分割数・表示も自動的に追従する
- 候補数によらず（2件のみの場合を含め）、各候補のラベルが重ならず、文字の向きが乱れず、対応する区画に正しく表示される

### 3.2 ルーレット

- 画面の主要な要素として、大きな円形のルーレットを表示する
- 候補数に応じて均等に分割し、区画ごとに色分けする（パステル系の複数色）
- ルーレット上部に、停止位置（選ばれた候補）を示す矢印（ポインター）を表示する
- 中央に「SPIN!」のようなボタンを配置する
- SPINボタン押下でルーレットが回転を開始し、勢いよく回り始めた後、2〜3秒程度かけて徐々に減速して停止するアニメーションを行う
- ルーレットの停止位置（矢印が指す区画）と、実際に選ばれたランチ候補は必ず一致する
- 停止後、選ばれた候補を大きく強調して表示する（例:「🎉 今日のランチは 🍣 寿司！」）

### 3.3 候補選定ロジック

- 候補の中からランダムに1件を選ぶ
- 選ばれた候補とルーレットの停止位置に矛盾が生じないようにする

## 4. 非機能要件

### 4.1 見た目・UI

- 勉強会で見せることを想定し、単純なサンプルHTML然としない、Webサービスらしい見た目にする
- 明るく楽しい雰囲気
- 背景は薄いオレンジ〜ピンク系のグラデーション
- コンテンツは白いカードUI、角丸、適度な影
- ルーレットはパステル系の複数色で色分け
- SPINボタンは目立つ配色
- 文字は読みやすいフォント・コントラストにする
- 絵文字を活用する
- ボタンや候補削除操作などにホバー時の反応（視覚的フィードバック）を付ける
- 回転アニメーション、結果表示時の拡大などの演出を入れる
- ただし、見た目のために必要以上に複雑な実装にはしない

### 4.2 レイアウト・レスポンシブ対応

- PC幅では左側に候補リスト、右側に大きなルーレットを配置する2カラムレイアウト
- スマホ相当の狭い画面では縦並びレイアウトに切り替える

### 4.3 技術制約

- HTML / CSS / JavaScript のみで実装する
- React、Vueなどのフレームワークは使用しない
- Canvas は使用しない（SVGやCSSなどでルーレットを表現する）
- 外部API、DB、外部UIライブラリは使用しない
- アプリ本体はローカルサーバーなしで `index.html` を `file://` で直接開いてもすべての機能が動作すること
- テストには Vitest を使用する（テスト実行時に Node.js / npm を使用することは許容する）

### 4.4 テスト・動作確認要件

#### 自動テスト（ロジック部分）

- 候補からランダムで1件選べること
- 候補追加ができること
- 候補削除ができること
- 候補が2件未満にはならない（2件の状態から削除できない）こと
- 選ばれた候補とルーレットの停止位置が矛盾しないこと

#### 手動確認（実ブラウザ）

以下の状態・環境で表示崩れやレイアウト崩れがないことを確認する。

- 初期状態（候補6件）
- 候補を追加した状態
- 最低数（2件）まで削除した状態
- PC相当の画面幅
- スマホ相当の画面幅
- `index.html` をローカルサーバーなしで直接開いた状態（`file://`）

特にルーレットのラベルについて、位置・向き・重なりに問題がないことを確認する。

## 5. 未確定事項

現時点で human_input.md から一意に決まらない詳細（候補の最大数の有無、SPIN連打時の挙動など）は、設計時に既存情報から妥当な範囲で判断する。人間への確認が必要な重大な不明点は生じていない。
